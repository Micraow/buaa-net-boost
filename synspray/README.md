# synspray：同 5 元组复读 SYN

验证一个假设：校园网 IPv6 的“新流首包丢失”是不是**只丢新流的第一个包**。如果是，那么在同一个 5 元组上把内核的 SYN 立刻复读几次（20/50/100ms），后面的副本会被当作该流的后续包放行，连接不必等内核 1 秒的 RTO。

## 原理

1. 内核 socket 正常 `connect()`，发出第一个 SYN；
2. 用 `AF_PACKET` 抓下这个 SYN（相同源端口、ISN、TCP 时间戳、选项）；
3. 重算 TCP 校验和（抓包可能是 checksum offload 的半成品）；
4. 用 raw IPv6 在同一 5 元组上按间隔复读同一份字节；
5. 内核 socket 收到任何一个 SYN-ACK 就完成握手。

复读包与内核 SYN 完全一致，服务端会把它当作 SYN 重传，不会建立多条连接。

## 构建与运行（需要 root）

```bash
cd synspray
gcc -O2 -Wall -o synspray synspray.c
sudo ./test.sh 2402:f000:1:400::2 443 10 4 20 3000
```

参数：目标 v6、端口、试验次数、复读份数、间隔 ms、超时 ms。

`test.sh` 先跑 10 次普通 connect 作为基线，再用 sudo 跑 10 次复读。

## 怎么看结果

| 结果 | 含义 |
|---|---|
| 复读成功率和普通接近，延迟也接近（1–2s） | 设备按会话/状态丢，复读没用；继续用多源端口（`--n 8`）或隧道 |
| 复读成功率明显更高，延迟降到几十毫秒 | 设备只丢新流首包；这个思路有效，值得做成透明层 |
| 复读成功率反而低 | 复读包被识别为异常/重复，触发限速；放弃 |

## 注意

- 需要 root：`AF_PACKET` 抓包 + `SOCK_RAW` 发送。
- 假设链路层是 14 字节以太网头、无 VLAN；当前 `wlan0` 满足。
- 服务端可能对重复 SYN 做速率限制；只在自己/授权网络测试。
- 如果验证有效，透明化的实现方式：
  1. 特权小助手 + 非特权代理通过 UNIX socket 请求复读（推荐，延迟可控）；
  2. eBPF `tc` egress 克隆 SYN（无延迟，但只能同时发多份，效果取决于设备策略）；
  3. 直接改内核/驱动（不现实）。
