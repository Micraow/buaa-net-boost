# UDP 多源端口首包竞速中继

对每个新的客户端 UDP 流，用 N 个连续源端口同时发送首个数据报；第一个收到目标回复的 socket 胜出，其余关闭；后续数据报只走胜者。

## 原理

- 出口按 5 元组哈希选路，UDP 首包落在坏桶时会被静默丢弃；同一 5 元组的重发也可能一直丢。
- 因此对**首个数据报**并行用 N 个源端口发送；哪个端口先收到目标回复，就用哪个。
- 判定胜者依赖“请求-响应”语义。纯单向 UDP（如 syslog）没有回复，无法判定，只能退化为随机端口或复制发送。

## 用法

```bash
../userspace/bin/udp-race --listen 18081 \
  --target 203.107.6.88 --target-port 123 \
  --n 5 --base 20003 --step 8
```

IPv6：`--family 6 --target <v6 地址>`。

然后让客户端把 UDP 发给 `127.0.0.1:18081`。当前实现是**固定目标**的中继，适合验证和单服务代理；通用代理需要把目标放进流键（见下）。

## 实测（NTP 203.107.6.88:123，每请求一个新流）

| 配置 | 成功 |
|---|---|
| N=1 | 14/20 |
| N=4 | 14/20 |
| **N=5** | **20/20** |
| N=5，复用同一流 | 20/20 |

N=4 和 N=1 都是 70%，说明 UDP 的坏桶相位在这段时间内有漂移，4 个端口不足以保证覆盖；N=5 稳定 100%。

## 关键实现点

- 首包并行发送后，用 `select` 等第一个回复；胜者保留，败者关闭。
- 每个流在 60 秒无活动后回收。
- 端口窗口按 `step=8` 滚动，避免复用同一 5 元组。
- 默认只跑一轮（`--rounds 1`）；需要重试时显式调大 `--rounds`。
- 源端口绑定 `wlan0`，避免走本机其他路由策略。

## 局限

- 只对“有回复”的 UDP 协议可靠；单向流量无法判定胜者。
- 通用 SOCKS5 UDP ASSOCIATE 需要把 (客户端地址, 目标地址, 目标端口) 作为流键，并把目标地址从 SOCKS5 UDP 头里解析出来；竞速逻辑相同。
- QUIC 可以按 UDP 流处理：首包竞速后，后续包走胜者；但要保证连接 ID 与客户端状态一致。
- 若途中有 NAT 改写源端口，桶选择不再可控，竞速退化为概率提升（N=5 仍有约 97%）。
- N 越大，首包复制越多；建议 5–6，不要过大。
